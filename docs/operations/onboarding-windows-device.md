# Підключення нового пристрою (Windows) до мережі Torgashka

> Модель (підтверджено Творцем 2026-09-13): **кожен пристрій напряму взаємодіє
> з БД ZBOX для синхронізації даних і має локальну копію БД, з якою працює.**
> HTTP-фасад на ZBOX відсутній — спосіб доставки конфігу: **копіювання 2 файлів**.

> 📘 **Докладний технічний довідник — [hub-and-nodes.md §15.0](./hub-and-nodes.md)**
> (порядок пошуку конфіга з посиланнями на код, права, діагностика, пастки, ризики).
> Ця інструкція — **канонічна для оператора**; обидві **не суперечать** одна одній
> (звірено 13.09.2026: шляхи конфіга, права `0600`, `.gitignore:149-150`, `ssl=off`,
> версії PG).

## Процедура

1. Скопіювати на новий пристрій **обидва** файли:
   - `db_sources.toml`
   - `.dbkey`

2. Покласти їх у каталог:
   ```
   %APPDATA%\Torgashka\
   ```
   Типово: `C:\Users\<Ім'я>\AppData\Roaming\Torgashka\`.
   Якщо каталогу немає — створити (у Проводнику вставити `%APPDATA%\Torgashka`
   в адресний рядок).

3. Файли мусять лежати **разом, в одному каталозі**. `.dbkey` — ключ
   розшифрування пароля БД; без нього пароль не читається.

4. Запустити Torgashka. На першому старті застосунок:
   - створить власний локальний кластер у `%APPDATA%\Torgashka\pgdata`;
   - підключиться напряму до ZBOX `10.179.55.210:5432`;
   - підтягне дані в локальну копію.

   > ⏳ **Що саме піднімає і використовує локальну копію — не встановлено.**
   > Спостережене на dev-машині **13.09.2026 не підтверджує цей пункт**: при
   > активному зовнішньому джерелі лог застосунку каже «`DATABASE_URL` ззовні …
   > embedded PG не потрібен» (авто-підйом копії пропущено), копія працює **окремим**
   > процесом (`data_dir=/home/anastasia/torgashka_pg_primary`, порт 5544, батько
   > `systemd --user`), і застосунок тримає **0** з'єднань до неї (2 — до ZBOX).
   > Узгоджено з `hub-and-nodes.md` §15.0(d). Рішення — за Творцем.

5. **Перевірка:** у застосунку мають з'явитися точки. Станом на 2026-09-13
   на ZBOX їх **2**.

## Чому саме `%APPDATA%\Torgashka\`

Код (`torgashka-infrastructure/src/db_sources.rs` → `stable_config_path()`)
шукає `db_sources.toml` у такому порядку:

```
1. env TORGASHKA_DB_SOURCES         (явний шлях)
2. %APPDATA%\Torgashka\db_sources.toml   ← stable: поряд із pgdata
3. <CWD>\db_sources.toml
4. <repo>/frontend/src-tauri/db_sources.toml   (dev-розкладка)
```

Крок 2 — єдиний, що не залежить від робочого каталогу запуску. На Windows
застосунок стартує з ярлика, тому CWD непередбачуваний: покладатися можна
лише на `%APPDATA%\Torgashka\`.

## Обмеження та застереження

| Питання | Стан |
|---|---|
| TLS до ZBOX | **`ssl=off`.** У межах ZeroTier прийнятно; при виході в звичайний інтернет потрібно закрити окремо. ⏳ Рішення **не прийнято** — те саме питання з варіантами (TLS / лише ZeroTier / комбінація) і `pg_hba 0.0.0.0` зафіксовано в [hub-and-nodes.md §0.2](./hub-and-nodes.md) |
| Версія PG | ZBOX = **14.24**, локальна копія = **17**. Фізична реплікація неможлива → синхронізація виключно на рівні застосунку |
| Секрети | `db_sources.toml` і `.dbkey` у `.gitignore` (рядки 149–150); у git не потрапляють |
| Права на файли | `db_sources.toml` — `0600`, `.dbkey` — `0600` |

## Заборонено

- Редагувати `db_sources.toml` вручну.
- Вважати зашифрований пароль (AES-256-GCM) помилкою й «виправляти» його.
- Переносити лише один із двох файлів.
