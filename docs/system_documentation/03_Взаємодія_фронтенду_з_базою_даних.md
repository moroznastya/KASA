# 03. Torgashka — Взаємодія фронтенду з базою даних

> Верифіковано за кодом `frontend/src` (React) та `frontend/src-tauri/crates/torgashka-api` станом на 2026-09-06.

## 1. Ланцюг: UI → БД

```
React-компонент (pages/)
  → services/*.ts (тонкі обгортки axios)
    → src/services/api.ts (axios instance + interceptors)
      → HTTP: Rust-фасад axum, base http://127.0.0.1:8000/api/v1
        (у dev через Vite proxy: '/api/v1')
        ├─ auth_middleware: JWT (Bearer), окрім публічних /auth/*, /health, /setup*, /devices/activate
        ├─ store_middleware: X-Store-Id → StoreCtx (task-local)
        ├─ StorePool: set_config('app.store_id'/'app.user_id') на з'єднанні
        └─ SQL: PostgreSQL (RLS фільтрує рядки точки/користувача)
  └── офлайн-режим (Tauri desktop):
        services/tauri/* → invoke('...') → Rust (src-tauri/src/commands) → SQLite offline.db
        фонова синхронізація: outbox → POST /api/v1/sync/push (коли онлайн)
```

**Ключове:** frontend **ніколи не ходить у PostgreSQL напряму**. Єдиний вхід —
HTTP-фасад axum на `127.0.0.1:8000` (вбудований у Tauri-бінарник). Усі
DB-доступи — у Rust-репозиторіях через `StorePool` (RLS-контекст на кожен
запит/транзакцію).

## 2. API-клієнт (`src/services/api.ts`)

```ts
const API_BASE_URL = import.meta.env.DEV
  ? '/api/v1'                                        // dev: Vite proxy → :8000
  : (import.meta.env.VITE_API_BASE_URL || 'http://127.0.0.1:8000/api/v1');
const api = axios.create({ baseURL: API_BASE_URL, timeout: 30000 });
```

**Request-interceptor (порядок):**
1. `Authorization: Bearer <accessToken>` (з `authStore`).
2. **X-Store-Id** — мультиточковість: заголовок додається на всі запити, КРІМ:
   - публічних шляхів: `startsWith('/auth/')`, `=== '/health'`;
   - store-management: `'/stores'`, `startsWith('/stores/')`, `'/user-stores'`
     (ці ендпоінти не потребують активної точки).
   - Якщо заголовок уже встановлено вручну (per-request override для
     офлайн-черги чеків зі своєю точкою) — не перезаписується.
   - Значення береться з `storeStore.activeStoreId` (localStorage `activeStoreId`).
3. `Content-Type: application/json`, крім FormData.

**Response-interceptor:**
- 401 → спроба refresh (`/auth/refresh`) з чергою `failedQueue`
  (паралельні запити чекають новий токен); при успіху — повтор оригіналу;
  при невдачі — logout.
- Інші статуси проброшуються у сервіси/компоненти.

**Наслідки для БД:** жоден бізнес-запит без `X-Store-Id` не доходить до SQL
(фасад віддає 400); запит з точкою, до якої користувач не прив'язаний → 403;
RLS — фінальний фільтр у PostgreSQL (тихо 0 рядків, якщо контекст не збігся).

## 3. Стейт-менеджмент і доступ до даних

| Store (Zustand) | Роль | Ключове |
|-----------------|------|---------|
| `authStore` | Токени, user, роль | accessToken/refreshToken; `role` (owner/admin/cashier) |
| `storeStore` | Активна точка | `activeStoreId` (localStorage), `stores[]`, `switchStore(id)` → persist + запити з новим X-Store-Id |
| `devicesStore` | Пристрої/активація | стан каси, token пристрою |
| `prroStore` | ПРРО статус/зміна | |
| `uiStore` | UI-стан | |

Кешування даних — TanStack Query (сервіси викликаються хуками
`useProducts`, `useReceipts`, `useUsers`, `useDocuments`, `useSuppliers`,
`useCategories`, `useWriteOffReasons`, `useOfflineSync`…).

## 6. Офлайн-режим і синхронізація з фронтенду

- `useOfflineSync.tsx` + `services/tauri/offline.ts`: перевірка доступності
  (`is_offline_available`, `check_online`), кешування товарів, збереження чеків
  локально, синхронізація при поновленні з'єднання.
- Локальні дані: SQLite `offline.db` (схема — у `02_… §7`). Rust-сторона —
  `torgashka-infrastructure/offline/commands.rs` (set_setting/get, enqueue,
  snapshots), Tauri commands у `src-tauri/src/commands/system.rs`.
- Pull довідників: `sync/master` (категорії/товари/норми/постачальники/
  працівники/налаштування) з версіями; Push транзакцій: outbox → `sync/push`
  з `client_uuid` (ідемпотентність).
- Чеки офлайн (ПРРО до 168 год): локальний `prro_queue`/XML у SQLite →
  при онлайні `sync/push` → сервер приймає (created|already_exists) → фіскалізація.

## 7. CORS / середовища

- Desktop (Tauri webview): origin `tauri://localhost` / `http://tauri.localhost`
  дозволений у CORS-шарі axum.
- Dev: `http://localhost:5173`, `http://127.0.0.1:5173` (Vite).
- Prod web-адмінка: додаткові origin через `TORGASHKA_CORS_ORIGINS` (comma-separated);
  веб-збірка `dist-admin/admin.html` говорить з тим самим API.
- Дозволені заголовки включають `X-Store-Id`; методи GET/POST/PUT/DELETE/PATCH/OPTIONS.

## 8. Патерн транзакційності (Rust-репозиторії → БД)

- `StorePool::begin()` → транзакція з RLS-контекстом (`is_local=true`).
- Атомарні бізнес-операції (чек + залишки + ledger + каса) виконуються в
  одній транзакції: `UPDATE stock … WHERE quantity >= qty` → якщо 0 рядків —
  відмова (недостатньо товару), rollback.
- Після commit/rollback RLS-контекст зникає; одиночні запити — з reset
  контексту (захист пулу). Деталі: `store_ctx.rs`, див. `02_… §5`.
