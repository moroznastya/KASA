## Швидкий зріз фактів (верифіковано по коду 2026-09-06)

- **Продукт:** Torgashka POS — фіскальна каса (ПРРО) для малого/середнього бізнесу України, що масштабується від 1 каси до мережі магазинів одного власника.
- **Продакшн-бекенд:** 100% Rust (`torgashka-api` = HTTP-фасад axum, вбудований у Tauri-бінарник; слухає `127.0.0.1:8000`).
- **Frontend:** React 18 + TypeScript + TailwindCSS v4 (Vite), два збірки: desktop (Tauri) + веб-адмінка (`admin.html`).
- **База даних:** PostgreSQL 15–17 (серверна БД власника) + локальний SQLite (`offline.db`) на кожній касі; опційно embedded PostgreSQL для single-store десктопа.
- **Модель даних:** ~40 таблиць PostgreSQL (schema.sql), 8 міграцій SQLite (offline), офлайн-черга outbox + версіонований pull довідників.
- **Мережа магазинів:** один власник — N точок (`stores`), ролі на рівні точки (`user_stores`), ізоляція через Row-Level Security + контекст запиту `app.store_id`/`app.user_id` (`StorePool`/`StoreCtx`).
- **Ізоляція власників:** database-per-owner (мета-таблиця `owners_db`, provisioning через `/api/v1/admin/db-sources/provision`).
- **Фіскалізація:** ПРРО-модуль `torgashka-prro` (gRPC до ДПС), офлайн до 168 годин, черга `prro_queue_items`.

## Застереження щодо застарілих документів

- `STRUCTURE.md`, `SYSTEM_STATE.md` у корені проєкту описують стан із назвами крейтів `kasa-*` і 17 таблицями — **фактично крейти перейменовані на `torgashka-*`, схема розрослась до ~40 таблиць** (мережевий рівень, ПРРО, боржники, касові операції тощо). Вважати їх історичними.
- `docs/database_schema.md` (копія в `sources/`) описує лише 16 legacy-таблиць Python-еталона — не повна картина поточної схеми.
