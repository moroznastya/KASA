## 2. Проблеми та ризики

### 🔴 ПРОБЛЕМА 1 (Висока): Друк через Tauri — не використовується ESC/POS для етикеток/цінників

**Опис:**  
І `PrintLabelsPage`, і `PrintPriceTagsPage` використовують ТІЛЬКИ `window.open() → print()` для друку.  
Це означає, що навіть у Tauri-оточенні друк іде через **браузерний діалог**, а не через **ESC/POS протокол**.

Для чеків є окремий механізм `usePrintAsImage` (html2canvas → PNG → Rust → ESC/POS), але для етикеток/цінників він **не використовується**.

**Наслідки:**
- Неможливість друку на термопринтерах без драйвера CUPS
- Втрата якості через браузерне масштабування
- Неможливість використання ESC/POS команд (обрізка, подача паперу)

**Рекомендація:**  
Використати `usePrintAsImage` для друку етикеток на термопринтер (Label) через Tauri, як це зроблено для чеків.

---

### 🔴 ПРОБЛЕМА 2 (Висока): Відсутність seed-скриптів для шаблонів цінників/етикеток

**Опис:**  
Для шаблонів чеків є seed-скрипти (`seed_update_receipt_58mm_template.py`, `seed_create_return_receipt_template.py`).  
Для шаблонів цінників та етикеток — **жодного** seed-скрипта.

Шаблони `price_tag`, `label` існують в БД, але немає можливості відтворити їх на свіжій БД.

**Наслідки:**
- При скиданні БД (тестування, розгортання) шаблони втрачаються
- Потрібно вручну створювати через API або UI

**Рекомендація:**  
Створити seed-скрипти для шаблонів `price_tag` та `label`:

```bash
backend/seed_create_price_tag_template.py
backend/seed_create_label_template.py
```

---

### 🟡 ПРОБЛЕМА 3 (Середня): Розмір @page жорстко закодований, не враховує налаштування

**Опис:**  
У `PrintLabelsPage.tsx` (рядки 109-111) CSS для друку:

```typescript
<style>
  @page { margin: 0; size: 58mm 40mm; }
  body { margin: 0; padding: 0; }
</style>
```

Але користувач може змінити ширину та висоту в `PrintSettingsPanel`. Зміни не передаються в CSS.

**Наслідки:**
- Друк етикеток нестандартного розміру (напр. 70×50 мм) буде зі зсувом
- Принтер може неправильно порізати етикетки

**Рекомендація:**  
Динамічно підставляти `settings.widthMm` та `settings.heightMm` у CSS `@page`:

```typescript
`@page { margin: 0; size: ${settings.widthMm}mm ${settings.heightMm}mm; }`
```

### 🟡 ПРОБЛЕМА 4 (Середня): Подвійний код друку в PrintLabelsPage та PrintPriceTagsPage

**Опис:**  
Обидві сторінки містять майже ідентичний код для друку через нове вікно (~40 рядків кожна).  
Відрізняється тільки `@page size` (A4 vs 58mm).

**Наслідки:**
- Дублювання коду
- При виправленні помилки в одному — легко забути виправити в іншому
- Ускладнене додавання нових типів друку (напр., друк QR-кодів окремо)

**Рекомендація:**  
Винести логіку друку в окремий хук `usePrintViaWindow` або в `printService.ts`:

```typescript
// printService.ts
export async function printViaWindow(html: string, pageSize: { width: number, height: number }) {
  const printWindow = window.open('', '_blank');
  // ...
}
```

### 🟡 ПРОБЛЕМА 5 (Середня): Немає вибору принтера на сторінках друку

**Опис:**  
На сторінках друку етикеток/цінників немає компонента вибору принтера.  
Використовується системний принтер за замовчуванням.

Для чеків є вибір принтера через `useReceiptPrinter` (береться з налаштувань або передається).

**Наслідки:**
- Неможливість вибрати інший принтер для етикеток (напр., окремий принтер для цінників)
- Користувачі з кількома принтерами не можуть вибрати потрібний

**Рекомендація:**  
Додати вибір принтера в `PrintSettingsPanel` (або в окремий блок), зберігати вибір у налаштуваннях.

---

### 🟡 ПРОБЛЕМА 6 (Середня): Немає підтримки QR-коду в шаблоні label

**Опис:**  
`PriceTagPrintService._render_single()` підтримує `{{barcode_image}}` з параметрами `barcode_type` (code128/qr) та `barcode_height_mm`.  
Але `PrintSettingsPanel` не дає змоги вибрати тип штрих-коду.

**Наслідки:**
- Неможливість надрукувати етикетку з QR-кодом
- Потенціал `barcode_image` не використовується

**Рекомендація:**  
Додати вибір типу штрих-коду (Code128 / QR) в `PrintSettingsPanel` та передавати `barcode_type` в API.

---

### 🟢 ПРОБЛЕМА 7 (Низька): Відсутність тестів для price_tag_print_service

**Опис:**  
Для `PriceTagPrintService` немає тестів, хоча він містить складну логіку:
- Генерація SVG штрих-кодів
- Handlebars-подібні умовні блоки
- Розрахунок сітки на A4
- Розмноження копій

**Наслідки:**
- Ризик регресії при зміні шаблону
- Важко перевірити правильність генерації

**Рекомендація:**  
Додати unit-тести для `PriceTagPrintService`, особливо для `_render_single` та `_calc_grid`.

---

### 🟢 ПРОБЛЕМА 8 (Низька): Немає обмеження на розмір `barcode_image` для QR

**Опис:**  
При генерації QR-коду `box_size_mm` помножується на 2 для стилю `width`.  
Для великих значень (напр. 40 мм) QR-код може вийти за межі етикетки.

**Наслідки:**
- QR-код може обрізатися на етикетці малого розміру

**Рекомендація:**  
Додати перевірку: якщо QR-код ширший за етикетку, зменшити його.

## 4. Пріоритети для вирішення

### 🥇 Першочергово (Спринт найближчий)

1. **Seed-скрипти для шаблонів** — швидке вирішення (30 хв), забезпечує відтворюваність
2. **Динамічний @page size** — невелика зміна, критично для коректного друку

### 🥈 Важливо (Наступний спринт)

3. **ESC/POS друк для етикеток через Tauri** — потребує адаптації `usePrintAsImage` для етикеток
4. **Вибір принтера** — UX покращення

### 🥉 Покращення

5. **Вибір типу штрих-коду** — невелике розширення
6. **Рефакторинг дубльованого коду** — clean code
7. **Тести** — якість коду
8. **QR overflow** — edge case
