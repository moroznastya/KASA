## 1. Рішення Творця (13.09.2026, дослівно — не інтерпретувати)

> **«Кожен пристрій напряму взаємодіє з БД ZBOX для синхронізації даних, і має
> копію локально БД, з якою взаємодіє.»**

## 2. Контекст (перевірено на живій системі 13.09.2026)

Перевірки виконано з робочої машини `10.179.55.165` (команди й результати —
`docs/operations/hub-and-nodes.md` §0.1, §15.0, §15.6):

* **ZBOX `10.179.55.210`:** порт `5432` — **ВІДКРИТИЙ**; `8000`, `80`, `443` —
  **ЗАКРИТІ**. Отже HTTP-фасаду на ZBOX **немає**.
* **Робоча машина:** застосунок `torgashka` тримає з'єднання **напряму** до
  `10.179.55.210:5432`; конфіг `db_sources.toml`: `active = "main"` →
  `host = 10.179.55.210`, `port = 5432`, `database = pos_system`,
  `user = postgres`, `password_encrypted` (AES-256-GCM), ключ `.dbkey` поряд
  (права 0600).
* **Локальна копія БД:** вбудований PostgreSQL; на цій машині — окремий процес,
  `data_dir=/home/anastasia/torgashka_pg_primary`, порт `5544`,
  `listen_addresses=127.0.0.1,192.168.0.160` — **два** слухачі
  (`ss -tlnp | grep 5544`; ⚠️ `postmaster.pid` віддає лише першу адресу списку →
  джерело істини `ss -tlnp`/cmdline). Штатно застосунок піднімає копію з
  `-h 127.0.0.1`, а env `TORGASHKA_PG_LISTEN_ADDRESSES` розширює listen на LAN
  (штатний порт вбудованої копії — `EMBEDDED_PG_PORT = 5433`;
  `embedded_pg.rs:1029-1041, 721`). ⏳ Розподіл ролей «локальна копія vs ZBOX» на рівні
  пулів застосунку — **відкрите питання** (див. §5).
* **Версії PG (підтверджено Творцем/NIKO 2026-09-13):** ZBOX = `PostgreSQL 14.24`,
  локальна копія = `PostgreSQL 17` → фізична потокова реплікація між major-версіями
  (14 → 17) **неможлива**: `pg_basebackup`/`primary_conninfo`/слоти реплікації в цій
  схемі **не застосовні**, механізмів `wal_level=replica` між ZBOX і пристроєм не
  будуємо → синхронізація **на рівні застосунку**. Рудименти реплікації на
  локальному кластері — ⏳ (`hub-and-nodes.md` §15.6-D).
* **Шифрування каналу:** `ssl = off`, `pg_hba`: `host all all 0.0.0.0
  scram-sha-256` → див. §5 (⏳ рішення).

## 3. Наслідки

1. **Синхронізація = спільна БД + локальні копії**, а не обмін HTTP-повідомленнями
   між вузлами та хабом. Транспорт — звичайний PostgreSQL-протокол до
   `10.179.55.210:5432`.
2. **Провіжн нового пристрою не потребує** адреси хаба `:8000`, токена вузла,
   знімка БД і майстра `/node-join` — достатньо `db_sources.toml` + `.dbkey`
   (процедура: `hub-and-nodes.md` §15.0).
3. **`GET /api/v1/sync/snapshot` по мережі недосяжний** (на ZBOX немає сервісу) —
   кроки 15.1–15.5 у `hub-and-nodes.md` позначено як **неактуальні/історичні**,
   не видалено.
4. Механізми HTTP-синку (`/sync/push`, `/sync/master`, `hub_forwarder`,
   `sync.hub_url`/`hub_token`, `join_code`) **лишаються в коді** як реалізація
   випадку «хаб — окремий HTTP-сервіс»; їхня доля для топології ZBOX — ⏳ рішення
   (перелік — `hub-and-nodes.md` §15.6).
5. ADR-0008 **не переписується**: він описує іншу топологію. Додано лише
   вказівник на цей ADR.

## 4. Альтернативи (не обрані, для історії)

| Альтернатива | Чому не обрана |
|---|---|
| Хаб як окремий HTTP-сервіс + push/pull (ADR-0008) | на підтвердженій топології фасаду на ZBOX немає (порт 8000 закритий) → провіжн вузлів і snapshot по мережі фізично не працюють |
| Фізична реплікація PostgreSQL (ADR-0007, ЕТАП 15–20) | скасована раніше (read-only вузол, split-brain, `pg_basebackup`-провіжн); див. `docs/operations/archive/` |
| Прямий доступ **без** локальної копії | суперечить рішенню Творця («має копію локально БД»), а також знімає offline-стійкість пристрою |

## 5. ⏳ Відкриті питання (за Творцем; тут рішень немає)

1. **Шифрування каналу ZBOX ↔ пристрій:** `ssl = off`. Варіанти — TLS на ZBOX
   (`sslmode=require`), або «лише ZeroTier» зі звуженням `pg_hba` з `0.0.0.0` до
   ZeroTier-підмережі, або комбінація. Поза ZeroTier `ssl = off` — неприйнятно
   (деталі — `hub-and-nodes.md` §0.2).
2. **Роль локальної копії:** хто і коли її піднімає на пристрої та чи працює
   застосунок з нею як з робочою БД (ZBOX — джерело синхронізації). На
   13.09.2026 застосунок мав з'єднання лише до ZBOX, локальна копія існувала
   окремим процесом (`hub-and-nodes.md` §15.0(d)).
3. **Доля HTTP-механізмів** (`hub_url`/`hub_token`, `hub_forwarder`,
   `join_code`, `/node-join`, `GET /sync/snapshot`, `role`/`lag_seconds` у
   `/sync/status`): вимкнути, лишити як «інший режим» чи видалити — рішення
   Творця (перелік місць — `hub-and-nodes.md` §15.6).
4. **Бекап/копія джерела** (ZBOX тепер єдина спільна БД): процедура бекапу —
   ⏳ не визначена (раніше блокер Б7 стосувався хаба).
